## Amendment-01 — السياسة الإحصائية والتصعيد

**القرار:** اعتماد سياسة تنفيذ إحصائية جديدة مع بقاء §§2.5 و14.2 من المرجع الأصلي دون تعديل.
**التاريخ:** 2026-10-10
**الأصل:** المرجع_النهائي_الموحد_المعتمد.md، §§2.5 و14.2؛ D-2026-10-10-01.

### النص الأصلي

§2.5، مقتطف حرفي:
````text
**نقاط بداية عدد التكرارات (حدّ أدنى لا سقف، حسب مستوى التحصيل فقط)**:

| مستوى التحصيل | نقطة البداية | التبرير |
|---|---|---|
| `C100%` | `200` | تباين صفري رياضياً (لا فسخ أبداً بسبب عدم السداد، لأن `collection_probability=1.0` يعني نجاح كل رمية حتماً)؛ هذا العدد لأغراض **إثبات الحتمية والتحقق التنفيذي فقط**، وليس لتقدير تباين إحصائي غير موجود أصلاً |
| `C85%` | `5,000` | تباين متوسط |
| `C70%` | `8,000` | تباين متوسط-مرتفع |
| `C50%` | `15,000` | تباين مرتفع (عند 50% السير العشوائي بلا انحراف متوسط، يتطلب تكرارات كثيرة) |
| `C30%` | `20,000` | تباين مرتفع جداً (انحراف واضح نحو التعثر) |

**سلّم التصعيد التلقائي (مستقل لكل توليفة، بلا سقف أقصى مسبق)**:
```
20,000 → 40,000 → 80,000 → 100,000 → 200,000 → ... (مضاعفة مستمرة حتى الاستقرار)
```

```python
ABSOLUTE_EPSILON = 1   # حد مطلق صغير للريال الواحد
REFERENCE_EPSILON = 1e-6

def is_stable(old_value, new_value):
    if abs(old_value) < REFERENCE_EPSILON:
        # القيمة القديمة صفر أو تقارب الصفر: استخدم فرقاً مطلقاً بدل نسبي
        return abs(new_value - old_value) < ABSOLUTE_EPSILON
    return abs(new_value - old_value) / abs(old_value) < 0.01   # تغيّر أقل من 1%
```

يُطبَّق هذا المعيار معاً (يجب أن يستقر **كل** المؤشرات التالية في آنٍ واحد بين تشغيلتين متتاليتين): `P10/P50/P90` للربح التراكمي الكلي (`Cumulative_Project_Profit`، البند 10.10)، `P90` للنقد النهائي (`Final_Cash`)، احتمال الخسارة (`Probability_of_Loss`)، `P90` لعدد الفسوخ (`Termination_Count`)، `P90` لعدد الأصول المحتفظ بها (`Held_Assets`).
````

§14.2، مقتطف حرفي:
````text
| مستوى التحصيل | نقطة البداية |
|---|---|
| C100% | 200 (لأغراض التحقق التنفيذي فقط، تباين صفري رياضياً) |
| C85% | 5,000 |
| C70% | 8,000 |
| C50% | 15,000 |
| C30% | 20,000 |

تصعيد تلقائي بالمضاعفة (`20,000 → 40,000 → 80,000 → 100,000 → 200,000 → ...`) حتى استقرار **كل** المؤشرات المذكورة في البند 2.5 معاً وفق دالة `is_stable` المُعرَّفة هناك. بلا سقف أقصى مسبق.
````

### النص المُحدَّث

1. `C100=1` لكل توليفة، للتحقق من الحتمية فقط؛ لا يستخدم CI. يُفحص التباين الصفري باستخدام `trial_id` وبذور مختلفة.
2. تبدأ كل توليفة في `C085/C070/C050/C030` من `300` تكرار.
3. التصعيد `300 → 600 → 1200 → 2400 → 4800 → 9600 → ...` بالمضاعفة المستمرة، بلا سقف، وبلا حد أدنى 5000، وبلا زيادة خطية `+50`.
4. **Gate A:** مطابقة المرجع/الدليل الذهبي المعتمد.
5. **Gate B:** نصف عرض فاصل الثقة 95% بتوزيع `t` أقل من `1%` من `|mean|` لكل من `Final_Net_Project_Equity` و`Partner1_Final_Entitlement` و`Partner2_Final_Entitlement`. عند الاقتراب من الصفر يُستخدم `CI_ABSOLUTE_EPSILON=1`، دون استحداث حد قرب آخر.
6. لا يكون الاستقرار النهائي `PASS` إلا بعد نجاح Gate A وGate B في ثلاث نقاط تصعيد متتالية. إذا نجح Gate B عند `300/600/1200` لكن تغيّر `P50` بأكثر من `5%` بين النقاط، تسجل الحالة `PRELIMINARY_STABLE` ويستمر التصعيد من `2400`، ولا تعتبر الحالة نجاحاً نهائياً.
7. تُسجل جميع نقاط التصعيد ونتائجها في `stability_history.json`.
8. تُلغى نقاط البداية التاريخية `C100=200` و`C085=5000` و`C070=8000` و`C050=15000` و`C030=20000` لأغراض التنفيذ الجديد.

**توضيح المصدر:** لم يُعثر في المرجع المرفق على عبارة حرفية `+50` في §16؛ لذلك لا يُنسب ذلك إلى نص المرجع. يلغى أي تفسير خطي `+50` خارج النص الحرفي بموجب هذا القرار.

### المواضع المتأثرة

§§2.5 و14.2 وسياسة الاستقرار وسجل `stability_history.json`. يبقى النص الأصلي نفسه دون تحرير ويُقرأ تاريخياً مع هذا الملحق.

### السبب

حسم أعداد البداية والتصعيد التنفيذية واعتماد فاصل ثقة ومقياس واضح للاستقرار.

### القيود

لا يعاد تشغيل أي trial مكتمل لهذا التعديل وحده. لا تكفي Gate B وحدها، ولا تعد `PRELIMINARY_STABLE` نجاحاً نهائياً. هذا الملحق لا يغيّر الكود أو نتائج التشغيل بذاته.

## Amendment-03 — خمسة أدوار تمثيلية

**القرار:** اعتماد خمسة أدوار لكل توليفة: `P50` و`P10` و`P90` و`LossCase` و`MaxCase`.
**التاريخ:** 2026-10-10
**الأصل:** المرجع_النهائي_الموحد_المعتمد.md، §§14.5–14.6 و15.3 و18.1 والملحق ب/البند 88؛ D-2026-10-10-03.

### النص الأصلي

§14.6، مقتطف حرفي:
````text
## 14.6 التكرارات التوضيحية الإلزامية (4 تكرارات، لكل توليفة)

بالإضافة إلى التكرار التمثيلي (P50)، تُختار وتُحفَظ سجلاتها اليومية الكاملة أيضاً:

| التكرار | معيار الاختيار |
|---|---|
| **P50** | نفسه التكرار التمثيلي أعلاه (البند 14.5) |
| **P10** | التكرار الأقرب للعشير الأدنى (`quantile 0.10`) من `Final_Net_Project_Equity` |
| **P90** | التكرار الأقرب للعشير الأعلى (`quantile 0.90`) من `Final_Net_Project_Equity` |
| **Loss Case** | التكرار صاحب **أدنى قيمة مطلقة** لـ`Final_Net_Project_Equity` على الإطلاق ضمن كل تكرارات هذه التوليفة، حتى لو كانت هذه القيمة موجبة (ربحاً) — يُستخدم لتمثيل أسوأ سيناريو فعلي وقع فعلاً في المحاكاة، لا سيناريو افتراضي |

كسر التعادل في P10/P90: أقل `trial_id`. تُصدَّر هذه التكرارات الأربعة مع سجلاتها اليومية الكاملة وملخصاتها المالية إلى ورقة `REPRESENTATIVE_CASES` في Excel (الباب الخامس عشر).
````

§15.3 و§18.1 والملحق ب/البند 88، مقتطفات حرفية:
````text
| 10 | `REPRESENTATIVE_CASES` | التكرارات التوضيحية الأربعة (P50، P10، P90، Loss Case، البند 14.6) مع سجلاتها اليومية الخام وملخصاتها المالية |
| 1 | نتائج مونت كارلو الخام | كل التكرارات في Parquet/SQLite، مع جميع الحقول المجمَّعة (لا سجلات يومية خام إلا للتكرارات الأربعة التوضيحية) |
| 5 | التكرارات التوضيحية الثلاثة الإضافية (P10، P90، Loss Case) | مع سجلاتها اليومية الكاملة (الباب 14.6) |
**88. التكرارات التوضيحية الإلزامية**: لكل توليفة، تُختار 4 تكرارات تمثيلية لحفظ سجلاتها اليومية الخام: P50 (الأقرب لوسيط `Final_Net_Project_Equity`)، P10، P90، Loss Case (أقل `Final_Net_Project_Equity` على الإطلاق ضمن التوليفة، حتى لو كان ربحاً موجباً) — يُستخدم لتمثيل أسوأ سيناريو فعلي.
````

### النص المُحدَّث

تُختار وتُحفظ خمسة أدوار تمثيلية لكل توليفة وتُصدَّر إلى `REPRESENTATIVE_CASES`:

| الدور | معيار الاختيار |
|---|---|
| `P50` | التكرار الأقرب إلى وسيط `Final_Net_Project_Equity` وفق معيار المرجع |
| `P10` | الأقرب إلى `quantile 0.10` لـ`Final_Net_Project_Equity` |
| `P90` | الأقرب إلى `quantile 0.90` لـ`Final_Net_Project_Equity` |
| `LossCase` | أقل قيمة لـ`abs(Final_Net_Project_Equity)`، أي الأقرب إلى الصفر، موجبة كانت القيمة أم سالبة |
| `MaxCase` | أعلى قيمة موجبة لـ`Final_Net_Project_Equity` |

كسر التعادل في جميع الأدوار بأصغر `trial_id`. تُحفظ السجلات اليومية الكاملة والملخصات المالية للأدوار الخمسة.

### المواضع المتأثرة

تُقرأ كل إشارة إلى أربعة أدوار أو ثلاثة أدوار إضافية ضمن المجموعة نفسها على ضوء هذا التعديل دون تعديل الأصل، ومنها §§14.6 و15.3 و18.1، §16.15/Test 160، تعليق `monte_carlo.py` في شجرة §19.2، والملحق ب/البند 88 وشجرة الملفات فيه، وأي إحالة أخرى للمجموعة نفسها.

### السبب

إضافة `MaxCase` وتثبيت تعريف `LossCase` بوصفه الأقل قيمة مطلقة والأقرب إلى الصفر.

### القيود

إذا لم توجد قيمة موجبة لـ`Final_Net_Project_Equity` في توليفة، فلا يضع القرار بديلاً لـ`MaxCase`؛ تطبق `UNDEFINED_BUSINESS_RULE` ويتوقف اعتمادها حتى توجيه صريح. لا يُختلق بديل ولا يُحرر المرجع الأصلي.

## Amendment-04 — معمارية طبقتي بناء Excel

**القرار:** اعتماد فصل معماري بين Orchestrator وAssembler.
**التاريخ:** 2026-10-10
**الأصل:** المرجع_النهائي_الموحد_المعتمد.md، §19.2؛ D-2026-10-10-04.

### النص الأصلي

§19.2، مقتطف حرفي من شجرة الملفات:
````text
├── monte_carlo.py              # تشغيل الـ25 توليفة، نقاط البداية المتكيفة، التصعيد، اختيار
│                          #   التكرار التمثيلي والتكرارات التوضيحية الأربعة، المسار الإحصائي اليومي
├── excel_builder.py           # بناء ملف Excel الكامل (185 ورقة)
├── validation.py               # مجموعة اختبارات القبول الآلية (163 اختباراً)
````

### النص المُحدَّث

هذا تصميم معياري للمسار المستهدف، وليس ادعاءً بأن الكود الحالي ينفذه:

1. `scripts/excel_builder.py` هو **Orchestrator**: CLI/config/mode، تحميل Parquet/SQLite، logging ومعالجة الأخطاء؛ ولا ينشئ أوراق العمل بنفسه.
2. `scripts/stage13_assemble.py` هو **Assembler**: `assemble_workbook` لتجميع 185 ورقة، والتجزئة والتحقق؛ بلا CLI مستقل.
3. الواجهة المعتمدة:
```python
def build_excel(dataset_path, output_path, mode="canonical"):
    data = load_dataset(dataset_path)
    return stage13_assemble.assemble_workbook(data, output_path, mode)
```
4. الأوضاع: `canonical` = `11005` تكرار افتراضياً؛ `sample` = `625` تكراراً؛ `demo` = تشغيل صغير سريع.

### المواضع المتأثرة

§19.2 وأي توثيق لاحق لواجهة بناء Excel؛ لا يُعاد تحرير المرجع الأصلي.

### السبب

فصل orchestration وتحميل البيانات وواجهة التشغيل عن إنشاء الأوراق والتجزئة والتحقق.

### القيود

لا يثبت هذا القرار وجود `scripts/excel_builder.py` أو توقيع `build_excel` أو مطابقة الكود الحالي. يُفحص التنفيذ ضمن CP منفصل؛ لا يشمل هذا التعديل أي كود إنتاجي.
